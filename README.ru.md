## Что внутри

Приложение небольшое, но в нём есть почти всё, что нужно настоящему мессенджеру:

- **Сначала офлайн**: экраны читают только кэш в Room. Чат, который уже открывали, открывается без сети, а новые сообщения придут, когда она появится.
- **Обновления в реальном времени** по WebSocket: новые сообщения, правки и удаления, чаты, поднимающиеся наверх списка, прочтения на другом устройстве.
- **Догонялка по закладке**: после фона или работы без сети приложение спрашивает у сервера только то, что изменилось с тех пор.
- **Отправка через outbox**: сообщение появляется сразу, а WorkManager отправляет его, когда есть сеть, по порядку и никогда дважды, в том числе после закрытия приложения.
- **Длинные чаты и длинные списки**: окна над кэшем, которые подгружают страницы вверх и вниз, открываются на первом непрочитанном и никогда не держат больше нескольких сотен элементов. Кнопка в тулбаре чата прыгает на случайное сообщение истории, чтобы это попробовать.
- **Отметки прочтения** с разделителем «Новые сообщения» и счётчиками непрочитанных, которые следуют за всеми устройствами.
- **Боты**, которые пишут каждые 10–30 секунд, и переключатель под списком чатов, который выключает их для всех.
- **Светлая и тёмная тема**, переключаются из списка чатов.

## Архитектура

Модули разложены по четырём уровням, и сборка проверяет, что ни один модуль не зависит от уровня выше своего:

```text
app/           app                                приложение
feature/       login, chats                       по одной фиче в каждом
crossfeature/  domain, data, ui                   код про чаты, нужный двум и более фичам
core/          designsystem, compose-utils,       ничего не знает про чаты
               mvi, network
```

Экраны работают на MVI на небольшом собственном ядре, DI — Koin с компиляторным плагином, навигация — Navigation 3. Как устроены модули, навигация, экраны, данные, синхронизация и сборка, рассказано в [документации по архитектуре](docs/architecture/ru/README.md).

## Тесты и CI

- **Тесты** работают на JVM и покрывают ядро MVI, логику экранов, слой данных с синхронизацией, контракт с сервером и скриншот каждого превью.
- **CI** запускается на каждый pull request: стиль кода, правила модулей, неиспользуемые зависимости, lint, тесты и сборка приложения, которая заодно проверяет граф Koin.

## Запуск

Проще всего скачать [APK из `main`](https://github.com/dmitriiecho/ChatApp/releases/download/main-latest/ChatApp.apk). Это release-сборка для Android 8.0 и новее, CI пересобирает её после каждого изменения кода в `main`.

Чтобы собрать приложение самому, нужны JDK 21, Android SDK и ключ сервера:

```properties
# local.properties
chatapp.apiKey=<ключ>
```

```sh
./gradlew :app:installDebug   # ставит приложение на подключённое устройство
```

Без ключа приложение собирается и запускается, но сервер отвечает 401, и экран входа показывает ошибку.

## Сервер

Чаты, сообщения и события отдаёт сервер на Ktor с SQLite в [`server/`](server/README.ru.md). Он развёрнут по адресу `http://2.56.204.151:8081/`, и им пользуются и debug-, и release-сборки.

## Сделано с AI-агентами

Приложение сделано с AI-агентами Claude Code, Cursor и Grok Build, на моделях Claude Opus и Grok. Агенты сильно ускоряют работу, но сами по себе хороший код не пишут: им нужны правила, пошаговое руководство и кто-то, кто проверит результат. Вот как это устроено в проекте:

- **Правила записаны для агентов**: [CLAUDE.md](CLAUDE.md) описывает раскладку модулей, стиль кода и соглашения для экранов и данных.
- **Изменения делаются маленькими шагами**, и каждый обсуждается и проверяется, прежде чем попасть в коммит.
- **Поведение проверяют тесты и CI** (см. [выше](#тесты-и-ci)), а каждое изменение ещё и пробуется на эмуляторе.
