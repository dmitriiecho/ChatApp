# Сервер ChatApp

[English version](README.md)

Сервер на Ktor для приложения: чаты, сообщения, журналы синхронизации и события в реальном времени, с ботами, которые пишут сами.

- **Адрес:** `http://2.56.204.151:8081/` (домена нет, поэтому нет и HTTPS).
- **Сборка:** отдельная Gradle-сборка, которую `settings.gradle.kts` приложения не подключает.
- **Форматы** — это DTO в [`../contract`](../contract/), которыми пользуется и приложение: included build, общий для обеих сторон.
- **Хранение:** один файл SQLite. Таблицы создаются при первом запуске, а пустая база заполняется примерными данными.

&nbsp;

## API

В каждом запросе два заголовка; без них сервер отвечает `401`.

| Заголовок | Значение |
|---|---|
| `X-Api-Key` | Ключ из `API_KEY`. Копия у приложения — в `local.properties` (`chatapp.apiKey`). |
| `X-User-Id` | Кто спрашивает: один из `GET /users`. Не нужен для самого `GET /users`. |

Запросы:

| Запрос | Возвращает |
|---|---|
| `GET /users` | Людей, от имени которых можно войти (ботов в списке нет) |
| `GET /conversations?limit` | Самые активные чаты пользователя |
| `GET /conversations?beforeSortKey&limit` | Чаты ниже этого sortKey |
| `GET /conversations/{id}` | Один чат, или 404, если пользователя в нём нет |
| `GET /conversations/changes?since&limit` | Журнал списка чатов пользователя после закладки |
| `GET /conversations/{id}/messages?limit` | Самые новые сообщения |
| `…/messages?beforeSeq` / `afterSeq` / `aroundSeq` | Сообщения старше, новее или вокруг seq |
| `GET /conversations/{id}/messages/changes?since&limit` | Журнал правок и удалений чата после закладки |
| `POST /conversations/{id}/messages` | Отправляет сообщение; возвращает его и чат |
| `POST /conversations/{id}/read` | Отмечает чат прочитанным до seq; возвращает чат |
| `GET /bots` | Работают ли боты |
| `PUT /bots` | Включает или выключает ботов для всех |
| `WS /events` | События пользователя, по одному JSON-объекту в текстовом кадре |

У каждого запроса и ответа, на которые опирается приложение, есть образец в [`api-samples/`](api-samples/), а `requests.json` в этой папке перечисляет метод и адрес каждого запроса. Тесты сервера проверяют, что он отвечает в точности как в образцах, а тесты приложения читают те же файлы, поэтому изменение формата или адреса на одной стороне валит тесты этой стороны.

### `GET /users`

```json
[{"id": "anna", "name": "Anna"}, {"id": "max", "name": "Max"}]
```

### `GET /conversations`

Страница чатов пользователя, самые активные сверху:

| Параметр | Значение |
|---|---|
| `limit` | От 1 до 100. |
| `beforeSortKey` | Следующая страница: чаты ниже этого `sortKey`. Если не указан — первая страница. |

```json
{
  "items": [
    {
      "id": "anna-bot",
      "title": "Oliver",
      "sortKey": 1,
      "version": 1,
      "unreadCount": 1,
      "lastSeq": 3,
      "lastReadSeq": 2,
      "lastMessage": {
        "id": "anna-bot:3",
        "conversationId": "anna-bot",
        "seq": 3,
        "version": 1,
        "authorId": "bot",
        "authorName": "Oliver",
        "text": "How are you?",
        "sentAtMillis": 1700000003000,
        "isDeleted": false
      }
    }
  ],
  "hasMore": false
}
```

- `lastSeq` — самое новое сообщение чата, `lastReadSeq` — докуда пользователь дочитал; когда есть непрочитанные, приложение открывает чат на `lastReadSeq + 1`.
- `GET /conversations/{id}` возвращает один чат в том же формате.

### `GET /conversations/{id}/messages`

Страница сообщений, самые новые сверху:

| Параметр | Значение |
|---|---|
| `limit` | От 1 до 100. |
| `beforeSeq` | Сообщения старше этого seq. |
| `afterSeq` | Сообщения новее этого seq. |
| `aroundSeq` | Сообщения вокруг этого seq, включая его. |

Без всех трёх — последняя страница; больше одного сразу — `400`. `limit` вне диапазона — `400` в любом запросе.

```json
{"items": [{"id": "anna-bot:3", "seq": 3, "text": "How are you?", "...": "..."}]}
```

### `GET …/changes`

Журнал синхронизации после закладки: `GET /conversations/changes` — для списка чатов, `GET /conversations/{id}/messages/changes` — для правок и удалений в чате.

| Параметр | Значение |
|---|---|
| `since` | Закладка, до которой клиент догнал. Если не указана — никаких изменений и текущая закладка. |
| `limit` | От 1 до 500. |

```json
{
  "changed": [{"id": "dm-anna-max", "sortKey": 3, "version": 2, "unreadCount": 1, "...": "..."}],
  "removedIds": [],
  "nextToken": "1",
  "hasMore": false,
  "resetRequired": false
}
```

В журнале сообщений нет `removedIds`: удалённое сообщение остаётся в нём «надгробием».

### `POST /conversations/{id}/messages`

```json
{"clientId": "c-1", "text": "Fine, thanks"}
```

В ответе — сообщение, как оно сохранено, и чат, каким его теперь видит отправитель:

```json
{
  "message": {"id": "anna-bot:4", "seq": 4, "authorId": "anna", "text": "Fine, thanks", "...": "..."},
  "conversation": {"id": "anna-bot", "sortKey": 3, "version": 2, "unreadCount": 0, "lastReadSeq": 4, "...": "..."}
}
```

- **`clientId`** — id сообщения у приложения: повтор с тем же id возвращает сообщение, отправленное в первый раз, а не публикует его снова.
- **Текст обрезается по краям** и после этого должен быть от 1 до 4 000 символов; иначе `400`.
- **Отправка отмечает чат прочитанным** для отправителя.

### `POST /conversations/{id}/read`

```json
{"seq": 3}
```

Возвращает чат. `lastReadSeq` только растёт: более старый seq ничего не меняет.

### `GET /bots`, `PUT /bots`

```json
{"enabled": false}
```

`PUT` принимает такое тело и возвращает значение, которое теперь действует; `GET` его возвращает. Переключатель общий для всего сервера, см. [Боты](#боты).

### `WS /events`

События пользователя, по одному в текстовом кадре, каждое с целым объектом в его текущем виде:

```json
{
  "type": "message.new",
  "message": {"id": "dm-anna-max:3", "seq": 3, "authorId": "max", "text": "Lunch at noon?", "...": "..."}
}
```

| `type` | Поле | Когда приходит |
|---|---|---|
| `message.new` | `message` | новое сообщение в одном из чатов пользователя |
| `message.changed` | `message` | правка или удаление |
| `conversation.updated` | `conversation` | новое сообщение, прочтение, правка последнего сообщения |
| `conversation.removed` | `conversationId` | пользователь вышел из чата; пока не отправляется, выйти нельзя |
| `bots.changed` | `enabled` | кто-то включил или выключил ботов |

Пуш несёт те же события, JSON-массивом в поле `events` ([`push-data.json`](api-samples/push-data.json)).

## Правила

Правила, на которые опирается приложение, по темам.

### Сообщения
- **`seq`** нумерует сообщения чата 1, 2, 3… без пропусков. Удалённое сообщение остаётся «надгробием» (`isDeleted`, пустой текст), поэтому дыра в кэше клиента — это часть, которую он не загрузил.
- **`version`** растёт с каждым изменением сообщения.

### Чаты
- **`sortKey`** уникален для пользователя и только растёт: новое сообщение поднимает чат наверх. Чаты только прыгают вверх.
- **`version`** растёт с каждым изменением чата, каким его видит пользователь: сообщение, прочтение, правка последнего сообщения.
- **`unreadCount`** считает чужие сообщения после `lastReadSeq`, не считая удалённых.
- **Название:** у группы своё; личный чат называется именем собеседника.

### Журналы синхронизации
- **Закладка** — позиция в журнале, строкой.
- **Порция** содержит каждый изменившийся объект один раз, в его текущем виде, вместе с `nextToken` и `hasMore`.
- **Журналы:** по одному на пользователя для списка чатов и по одному на чат для правок сообщений. Каждый хранит последние 5 000 записей.
- **`resetRequired`** — ответ на закладку ниже хранимых записей, дальше самой новой (базу пересоздали) или не число.

### События
- **Новое сообщение** шлёт каждому участнику чата `message.new` и `conversation.updated`.
- **Правка или удаление** шлёт `message.changed`, а если это последнее сообщение, ещё и `conversation.updated`.
- **Прочтение** шлёт `conversation.updated` на все сокеты читателя, чтобы другие устройства сбросили счётчик непрочитанных.
- **Переключатель ботов** шлёт `bots.changed` на каждый открытый сокет, чей бы он ни был. Журнала у него нет: клиент читает `GET /bots` при каждом подключении.
- **Медленный сокет**, отставший на 256 событий, закрывается; клиент переподключается и синхронизируется.
- **У ботов** нет ни сокетов, ни журналов.

## Ограничения

Запись ограничена на пользователя, а тело каждого запроса — по размеру:

| Что | Ограничение |
|---|---|
| Отправка сообщений | 10 в минуту на пользователя, потом `429` |
| Прочтения | 30 в минуту на пользователя, потом `429` |
| Тело запроса | 16 КБ, потом `413` |

## Данные

Пустая база получает трёх людей (Anna, Max, Kate) и 220 ботов. У каждого человека есть:

- **личные чаты** с двумя другими;
- **группа** Project team с ними и четырьмя ботами;
- **чат с Historian** на 3 000 сообщений, больше окна чата в приложении;
- **215 чатов с ботами**, больше окна списка в приложении.

В некоторых чатах сразу есть непрочитанные. Данные каждый раз одинаковые (фиксированное зерно случайности).

### Боты
- **Сами по себе:** каждые 10–30 с бот пишет в один из своих чатов; иногда вместо этого правит (5 %) или удаляет (2 %) своё последнее сообщение.
- **Ответы:** бот отвечает человеку, который написал ему в личный чат, через 2–5 с.
- **Переключатель:** `PUT /bots` выключает их для всего сервера, ответы тоже. Значение хранится в базе (`settings`), поэтому переживает перезапуск и деплой; по умолчанию боты включены.
- **Совсем без ботов:** `BOTS_ENABLED=false`, как в тестах; переключатель тогда только хранит значение.

## Запуск

Собственный Gradle wrapper сервера лежит в этой папке:

```sh
./gradlew test            # тесты, включая образцы API
API_KEY=dev ./gradlew run # локально на порту 8081 с chat.db в server/
./gradlew spotlessCheck   # стиль кода (правила в корневом .editorconfig); spotlessApply исправляет
./deploy.sh               # проверить, собрать и перезапустить сервер на этой машине
```

`deploy.sh` запускает сервер как пользовательский сервис systemd `chatapp-server` из копии в `~/server/chatapp/app`:

| Путь | Что хранит |
|---|---|
| `~/server/chatapp/data/chat.db` | Базу; деплой её сохраняет |
| `~/server/chatapp/server.env` | `API_KEY`, создаётся при первом деплое (права 600) |

```sh
journalctl --user -u chatapp-server -f        # логи, включая каждый запрос
systemctl --user status chatapp-server        # проверить, запущен ли (а также stop, restart)
```

Чтобы начать заново со свежими данными, остановите сервис, удалите `chat.db` и запустите его снова: клиенты тогда получат `resetRequired`.
