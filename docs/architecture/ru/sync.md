# Синхронизация

[English version](../en/sync.md) · [Все страницы](README.md)

Кэш в Room должен поспевать за сервером: новые сообщения, правки и удаления, подъём чатов в списке, прочтение на другом устройстве и сообщения, которые пользователь написал без сети. Этим занимаются пять механизмов, каждый для своего случая, и все они только пишут в Room (см. [Данные](data.md)).

&nbsp;

## Кто что приносит

Каждый механизм закрывает то, чего не закрывают остальные:

| Механизм | Когда работает | Что приносит |
|---|---|---|
| [Сокет событий](#сокет-событий) | пока приложение на экране | каждое изменение, сразу как оно случилось |
| [Синхронизация по токену](#синхронизация-по-токену) | при каждом подключении сокета и при открытии чата | то, что пропущено, пока сокет был закрыт |
| [Пуши](#пуши) | точка входа для сервиса пушей; FCM пока нет | события, пока приложение в фоне |
| [Outbox](#outbox) | когда есть что отправить и есть сеть | сообщения пользователя, по порядку, в том числе после закрытия приложения |
| [Отметки прочтения](#отметки-прочтения) | пока пользователь листает чат | докуда пользователь дочитал, на все его устройства |

&nbsp;

## Сокет событий

`RealtimeConnection` держит WebSocket-соединение с `ws://…/events`, и сервер шлёт по нему события пользователя, по одному JSON-объекту в кадре:

| Событие | Значит | Приложение |
|---|---|---|
| `message.new` | новое сообщение в чате | кладёт его в кэш, только если оно продолжает то, что уже есть в кэше (`seq == maxSeq + 1`) |
| `message.changed` | правка или удаление | обновляет сообщение, если оно в кэше |
| `conversation.updated` | новое сообщение, прочтение, переименование | обновляет чат; чат, который поднялся наверх, появляется в списке |
| `conversation.removed` | пользователь вышел из чата; сервер его пока не шлёт, потому что в UI выйти из чата нельзя | удаляет чат и его сообщения |
| `bots.changed` | кто-то включил или выключил ботов на сервере | обновляет переключатель под списком чатов |

- **Одиночное новое сообщение в кэш не кладётся.** Если предыдущего сообщения в кэше нет, получился бы кусок истории с дырой под ним, и без сети чат открылся бы на нём. Недостающие сообщения загрузятся при открытии чата.
- **Неизвестный тип события пропускается**, поэтому новый тип на сервере не ломает старые версии приложения.
- **События, отправленные, пока приложение было без сети, теряются**: после переподключения то, что они изменили, подтягивает синхронизация по токену.

Сокет открыт, только пока пользователь вошёл в аккаунт и приложение на экране. `RealtimeRunner` в `:app` управляет им через `ProcessLifecycleOwner`:

```kotlin
sessions.map { it?.userId }.distinctUntilChanged().collectLatest { userId ->
    if (userId == null) return@collectLatest
    process.lifecycle.repeatOnLifecycle(Lifecycle.State.STARTED) {
        connection.connectAndListen()
    }
}
```

- **В фоне сокет закрывается**: Android всё равно оборвал бы его, а на это время есть пуши.
- **`ProcessLifecycleOwner` сообщает об уходе в фон примерно через 700 мс**, поэтому поворот экрана не переподключает сокет.
- **После обрыва сокет переподключается** с растущей паузой (1 с, 2 с, 4 с… до 30 с), чтобы не заваливать упавший сервер попытками, или сразу, как только появится сеть (`NetworkMonitor` на `ConnectivityManager`).

## Синхронизация по токену

Сервер ведёт журналы изменений: по одному на список чатов каждого пользователя и по одному на правки и удаления в каждом чате. **Токен** — это позиция в журнале. Приложение хранит токен, до которого уже дошло, и запрашивает всё, что было после него:

| Ситуация | Приложение спрашивает | Получает |
|---|---|---|
| первый запуск | `changes` без токена | никаких изменений, только текущий токен; затем загружается первая страница |
| токен есть | `changes?since=<токен>` | что изменилось после него, и следующий токен; порциями, пока `hasMore` не станет false |
| токен слишком старый | то же | `resetRequired`: журнал так далеко назад уже не хранится, поэтому список начинается заново с первой страницы, а кэш чата удаляется |

Изменения и новый токен записываются в одной транзакции:

```kotlin
db.withWriteTransaction {
    conversationDao.upsertIfRelevant(changes.changed.map { it.toEntity() })
    db.removeConversations(changes.removedIds)
    metaDao.upsert(metaDao.get()!!.copy(syncToken = changes.nextToken))
}
```

Если что-то упадёт посередине, не запишется ни то, ни другое, и следующая синхронизация снова начнёт со старого токена. Токен никогда не уходит дальше неприменённых изменений.

- **Список чатов** (`ConversationsSync`) синхронизируется при каждом подключении сокета, включая первое. Это забота приложения, а не экрана, поэтому чаты синхронизируются, даже если приложение открылось сразу на экране чата.
- **Правки в чате** (`MessageChangesSync`) синхронизируются при открытии чата, а после каждого подключения — для десяти последних открытых чатов, чтобы потом и без сети они открывались с актуальным текстом. Новых сообщений в этом журнале нет: их загружает окно чата.
- **Порядок важен, когда список начинается заново**: сначала токен, потом страница. Тогда чат, изменившийся между двумя запросами, придёт и в странице, и из журнала, а это безвредно (`version`). При обратном порядке изменение, сделанное между страницей и токеном, не попало бы никуда.

## Пуши

FCM в проекте нет, но место для него есть. `RealtimeHandler.onPush(data)` принимает данные пуша, применяет его события так же, как события сокета, и возвращает те, что ещё актуальны, — чтобы сервис пушей решил, какое уведомление показать:

```kotlin
suspend fun onPush(data: Map<String, String>): List<RealtimeEventDto> {
    val raw = data[PushData.EVENTS] ?: return emptyList()
    val events = networkJson.parseToJsonElement(raw).jsonArray.mapNotNull { decodeEventOrNull(it) }
    events.forEach { onEvent(it) }
    return events.filterNot { isStale(it) }
}
```

Пуш, который задержался, пока телефон спал, может сообщать о чате, который с тех пор прочитали на другом устройстве: `version` не даст ему перезаписать Room, а `isStale` — показать уведомление. Формат пуша — в [`server/api-samples/push-data.json`](../../../server/api-samples/push-data.json).

## Outbox

Отправка сообщения не ждёт сети. Сообщение сначала записывается в Room и сразу появляется в чате с подписью «Отправляется»:

```text
Отправить ──▶ outgoing_messages (Room) ──▶ WorkManager ──▶ OutboxSender.drain() ──▶ POST …/messages ──▶ messages (Room)
```

- **Очередь отправляет одна уникальная задача** WorkManager (`OutboxWorker`). Она запускается только при наличии сети, после сбоя повторяется с растущей паузой и работает даже после закрытия приложения.
- **По одному, начиная с самого старого**, поэтому сообщения приходят в том порядке, в каком их написали.
- **Повторная отправка безвредна**: у каждого сообщения есть `clientId`, и на повтор сервер возвращает то же сообщение, а не публикует его второй раз.
- **При сбое сети** ждущие сообщения показываются как «Не отправлено. Нажмите, чтобы повторить»; нажатие снова ставит в очередь их все, ведь после неотправленного сообщения не ушло и ничего другого.
- **Отправленное сообщение остаётся на экране**: оно попадает в кэш как продолжение чата. Если, пока пользователь был без сети, пришли чужие сообщения, которых нет в кэше, `OutboxSender` сначала догружает эту дыру, до трёх страниц.

Задача ставится с `APPEND_OR_REPLACE`, а не `KEEP`: с `KEEP` сообщение, поставленное в очередь в тот момент, когда текущая задача заканчивается, ждало бы следующего повода для отправки.

## Отметки прочтения

Чат прочитан до самого нового сообщения, которое пользователь видел на экране. Экран сообщает об этом Intent'ом `MessagesSeen(seq)`, а Executor отправляет не больше одной отметки в секунду, пока пользователь листает:

- **Сервер отвечает чатом**, уже с `unreadCount = 0`, и шлёт `conversation.updated` на другие устройства пользователя, чтобы их счётчики тоже сбросились.
- **Без сети отметка молча не отправляется**: её отправит следующее сообщение, которое увидит пользователь.
- **Разделитель «Новые сообщения»** ставится при открытии чата над первым непрочитанным сообщением и остаётся, пока чат открыт, даже после того, как отметка ушла.

## Переключатель ботов

Переключатель под списком чатов показывает текущее состояние сервера, а это не то содержимое, которое нужно показывать без сети. Поэтому это единственное, что хранится в памяти, а не в Room (`BotsRepositoryImpl`):

- **Состояние неизвестно до первого подключения сокета**, при котором читается `GET /bots`; до тех пор переключателем нельзя пользоваться.
- **Потом он следует за `bots.changed`**, поэтому изменение с другого устройства переключает его само.
- **Нажатие сразу переключает его**, пока запрос ещё в пути; без сети переключатель возвращается назад, а снэкбар объясняет почему.
